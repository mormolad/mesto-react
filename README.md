# 📦 ПОЛНАЯ СПЕЦИФИКАЦИЯ ЭПИКОВ (БЕЗ КОДА)

## 🎯 ВВЕДЕНИЕ

Этот документ описывает полную архитектуру и функциональность приложения-помощника для турагента с интерфейсом для туриста. Разработка ведется одним разработчиком с использованием современного технологического стека: **Next.js 16** (фронтенд) и **NestJS 11** (бэкенд).

---

### BE-01: Система аутентификации и авторизации

**User Stories:**

1. **Регистрация пользователя**
   - Пользователь вводит email, телефон (опционально), пароль
   - Система валидирует формат email и сложность пароля
   - На email отправляется ссылка для подтверждения
   - После подтверждения создается учетная запись с ролью по умолчанию (турист)
   - Агенты создаются только через админ-панель

2. **Логин с JWT-токенами**
   - Пользователь вводит email и пароль
   - Система проверяет учетные данные и статус подтверждения
   - Выдаются два токена: access (15 мин) и refresh (7 дней)
   - Токены хранятся в httpOnly cookies (защита от XSS)
   - Refresh token сохраняется в Redis с привязкой к устройству

3. **2FA через TOTP**
   - Пользователь включает 2FA в настройках
   - Генерируется секретный ключ и QR-код (Google Authenticator)
   - Пользователь сканирует QR-код и вводит текущий код для верификации
   - После верификации 2FA становится обязательным при входе
   - Отключение 2FA требует ввода текущего кода

4. **Восстановление пароля**
   - Пользователь нажимает «Забыли пароль?» и вводит email
   - Система отправляет одноразовый токен на email (срок жизни 1 час)
   - По ссылке пользователь попадает на форму сброса пароля
   - Новый пароль хешируется и сохраняется, старые сессии инвалидируются

5. **Ролевая модель**
   - **Турист:** просмотр подборок, подписки, управление профилем
   - **Агент:** полный доступ к CRM, подборкам, финансам, клиентам
   - **Админ:** управление пользователями, системные настройки, просмотр логов
   - Middleware проверяет роли при каждом запросе к защищенным эндпоинтам

6. **Refresh token ротация**
   - При истечении access токена клиент отправляет refresh token
   - Система проверяет refresh token в Redis
   - Выдается новая пара токенов, старый refresh инвалидируется
   - При компрометации (использование старого токена) все сессии пользователя сбрасываются

7. **Логаут**
   - Пользователь нажимает «Выйти»
   - Refresh token удаляется из Redis
   - httpOnly cookies очищаются на клиенте
   - Доступ к защищенным ресурсам блокируется

### FE-01: Интерфейс аутентификации

**User Stories:**

1. **Страница регистрации**
   - Форма с полями: email, телефон (опционально), пароль, подтверждение пароля
   - Валидация в реальном времени (email корректный, пароль 8+ символов)
   - Сообщение об успешной регистрации с предложением подтвердить email
   - Кнопка «Отправить повторно», если письмо не пришло

2. **Страница входа**
   - Форма: email, пароль
   - Чекбокс «Запомнить меня» (увеличивает срок жизни refresh токена)
   - Если включена 2FA — дополнительное поле для кода
   - После успешного входа редирект на дашборд в зависимости от роли

3. **Настройка 2FA**
   - Переключатель «Включить двухфакторную аутентификацию»
   - QR-код для сканирования в приложении-аутентификаторе
   - Поле для ввода кода подтверждения
   - После включения — показ backup-кодов (одноразовые коды для восстановления доступа)

4. **Восстановление пароля**
   - Страница «Забыли пароль?» с полем email
   - Страница сброса пароля с формой (новый пароль + подтверждение)
   - Сообщение об успешном сбросе и кнопка перехода к логину

5. **Ролевая навигация**
   - После входа middleware определяет роль и показывает соответствующий интерфейс
   - Агент видит: дашборд, туры, подборки, клиенты, финансы, база знаний
   - Турист видит: мои подписки, история просмотров, настройки профиля
   - Админ видит дополнительно: управление пользователями, системные логи

6. **Авто-логаут**
   - При истечении access токена middleware редиректит на логин
   - Сохраняется URL, на который хотел попасть пользователь (для редиректа после входа)
   - При истечении refresh токена требуется полная повторная авторизация

### BE-02: Поиск и агрегация туров

**User Stories:**

1. **CRUD отелей**
   - Создание отеля: название, страна, город, координаты (для карты), описание, удобства (список), рейтинг (1-5), фото (до 10)
   - Редактирование и удаление отеля
   - Поиск отелей по названию, стране, городу, удобствам

2. **CRUD туров**
   - Создание тура: привязка к отелю, даты заезда/выезда, цена, количество мест, тип питания, описание
   - Копирование тура (для быстрого создания соседних дат)
   - Редактирование и удаление (мягкое удаление с сохранением истории)

3. **Интеграция с API туроператоров** (v2, после MVP)
   - Адаптеры для 1-2 туроператоров (Pegas, Coral Travel и др.)
   - Нормализация данных в единую схему (разные названия полей → единый формат)
   - Graceful degradation: если API не отвечает, показываем кэш с пометкой «цены могут быть неактуальны»
   - Circuit Breaker: после 5 ошибок подряд отключаем интеграцию на 5 минут

4. **Поиск туров с фильтрами**
   - Фильтры: страна, город, даты (заезд/выезд), бюджет, тип питания, звездность отеля, рейтинг, теги (пляжный, экскурсионный, семейный)
   - Поиск через PostgreSQL с индексами (pg_trgm для текста, GiST для дат)
   - Сортировка: по цене (возраст/убыв), по дате, по рейтингу, по популярности

5. **Кэширование результатов**
   - Результаты поиска кэшируются в Redis (TTL: 5-15 минут в зависимости от запроса)
   - Ключ кэша = хеш от всех параметров запроса
   - Инвалидация кэша при изменении цен (по тегам или массово)

6. **Календарь низких цен**
   - Агрегация цен по отелям на 30 дней вперед
   - Heat map (чем дешевле, тем темнее зеленый)
   - Возможность переключения между отелями и направлениями

7. **Сравнение туров**
   - Выбор до 4 туров для сравнения
   - Табличное представление с подсветкой различий
   - Возможность сохранить сравнение в подборку

### BE-03: Подборки (Collections)

**User Stories:**

1. **CRUD подборок**
   - Создание: название, описание, шаблон оформления (из 3-5 вариантов)
   - Редактирование: можно менять название, описание, состав
   - Удаление: мягкое удаление (сохраняется в архиве)
   - Копирование: создание подборки на основе существующей

2. **Управление составом**
   - Добавление туров/отелей из поиска
   - Порядок элементов можно менять (drag-n-drop)
   - Каждый элемент можно удалить
   - Максимум 20 элементов в одной подборке (для сохранения производительности)

3. **Фиксация цен**
   - Переключатель «Фиксировать цены» при публикации
   - При включении — создается snapshot всех цен на момент публикации
   - Турист видит зафиксированные цены, даже если они выросли
   - Агент видит актуальные цены в редакторе

4. **Публикация и ссылки**
   - При публикации генерируется уникальный токен (UUID)
   - Публичная ссылка: `/collection/{token}`
   - Ссылка работает без авторизации
   - Можно отозвать ссылку (сделать подборку приватной)

5. **Версионность**
   - При каждом изменении подборки сохраняется версия (diff)
   - История изменений: дата, автор, что изменилось (добавлен тур X, удален тур Y)
   - Возможность отката к любой версии

6. **Экспорт**
   - PDF: красиво оформленный документ с турами, ценами, фото
   - Текст для мессенджеров: форматированный текст для WhatsApp/Telegram
   - Ссылка: короткая ссылка на подборку (с UTM-метками)

7. **Трекинг**
   - При открытии публичной ссылки логируется: дата, IP, user-agent
   - Агент видит статистику просмотров в дашборде
   - Аналитика: сколько туристов подписалось после просмотра

### BE-04: Умный подписчик

**User Stories:**

1. **Профиль предпочтений туриста**
   - Сохраняются: канал связи (email/Telegram), частота уведомлений
   - История уведомлений: что отправляли, когда, прочитал/нет
   - Возможность отписаться одним кликом

2. **Фоновый мониторинг**
   - Cron-воркер запускается каждые 2 часа (можно настроить)
   - Проходит по всем активным подпискам
   - Для каждой подписки получает актуальную цену тура

3. **Сравнение цен**
   - Сравнивает новую цену с последним сохраненным снимком
   - Рассчитывает процент изменения
   - Определяет триггер: падение на 5%, рост (редко), «горящий тур» (осталось мало мест)

4. **Умные триггеры**
   - Цена упала на 5% и более → отправляем уведомление
   - Осталось < 3 мест → отправляем уведомление с пометкой «Осталось мало мест»
   - Цена выросла более чем на 10% → опциональное уведомление

5. **Очередь уведомлений**
   - Уведомления попадают в BullMQ очередь
   - Приоритет: горящие туры > падение цены > обычные
   - Retry: при ошибке отправки — повтор через 5 минут, максимум 3 попытки

6. **Отправка через Telegram Bot API**
   - Форматирование сообщения: название тура, старая/новая цена, ссылка на подборку
   - Кнопки: «Посмотреть подборку», «Отписаться»
   - Отслеживание кликов по кнопкам (аналитика)

7. **Отправка через email**
   - HTML-шаблон с адаптивным дизайном
   - Трекер открытий (прозрачная 1x1 пиксель)
   - Ссылка на управление подписками внизу письма

8. **Частота уведомлений**
   - «Сразу»: уведомление при любом изменении
   - «Раз в день»: накопление изменений, отправка в 10:00
   - «Раз в 3 дня»: отправка дайджеста

9. **История снимков цен**
   - Каждое изменение цены сохраняется в таблицу price_history
   - Используется для графиков в интерфейсе туриста
   - Хранится 90 дней, потом архивируется

6. **Напоминания**

   - Типы: день рождения клиента, дата вылета, дата возврата, «перезвонить через 3 дня»

7. **Экспорт данных клиента (GDPR)**
   - Кнопка «Скачать данные» в карточке клиента
   - Генерация JSON-файла со всеми данными клиента
   - Скачивание через браузер

8. **Удаление данных (GDPR)**
   - Кнопка «Удалить аккаунт» в карточке клиента (требует подтверждения)
   - Мягкое удаление: помечается как deleted, персональные данные обнуляются
   - Через 30 дней — физическое удаление из БД

### BE-06: Финансовый модуль

**User Stories:**

1. **Курсы валют**
   - Автоматическая загрузка курсов ЦБ РФ (ежедневно в 12:00)
   - Хранение истории курсов (для расчетов на любую дату)
   - Ручной ввод курса (если авто-загрузка недоступна)
   - Приоритет: ручной курс > авто-курс

2. **Калькулятор маржи**
   - Входные параметры: цена тура, комиссия агента (%), расходы (реклама, трансфер)
   - Расчет: маржа = цена × комиссия/100 − расходы
   - Расчет в реальном времени при изменении параметров
   - Сохранение результата в сделку

3. **Учет доходов по сделкам**
   - Каждая закрытая сделка добавляется в доходы
   - Сумма дохода = цена × комиссия/100
   - Автоматический пересчет в рубли по курсу на дату сделки

4. **Учет расходов**
   - Категории: реклама, подписки, комиссии платежных систем, прочее
   - Ручное добавление расходов с привязкой к сделке или без
   - Загрузка чеков/документов (опционально)

5. **Агрегация по периодам**
   - День, неделя, месяц, год, произвольный период
   - Группировка по агентам, направлениям, типам туров
   - Сравнение с предыдущим периодом (рост/падение)

6. **Экспорт отчетов**
   - CSV: для загрузки в Excel/Google Sheets
   - Excel: форматированный файл с формулами
   - PDF: готовый отчет для бухгалтерии
   - Отправка на email (опционально)

   - Кнопка «Сохранить в сделку» (открывает форму создания сделки)

4. **Управление курсами валют**
   - Таблица: валюта, курс, дата обновления
   - Кнопка «Обновить курсы» (ручной запрос к ЦБ)
   - Поле для ручного ввода курса (с комментарием)
   - История изменений курсов

5. **Экспорт отчетов**
   - Модальное окно: выбор формата (CSV, Excel, PDF), выбор периода, выбор данных
   - Фоновая генерация (если отчет большой)
   - Ссылка на скачивание приходит в уведомления

### BE-07: Telegram Bot

**User Stories:**

1. **Webhook для Telegram Bot API**
   - Эндпоинт `/webhooks/telegram` принимает обновления от Telegram
   - Проверка подписи (секретный токен)
   - Асинхронная обработка (не блокируем ответ)

2. **Обработка команд**
   - `/start` — приветствие, кнопка «Открыть приложение» (Mini App)
   - `/subscribe [токен]` — подписка на подборку
   - `/help` — список команд
   - `/unsubscribe` — отписка от всех подборок

3. **Callback query (кнопки)**
   - Кнопка «Посмотреть подборку» — открывает Mini App с глубокой ссылкой
   - Кнопка «Отписаться» — отписывает от конкретной подборки
   - Кнопка «Подтвердить» — подтверждение подписки

4. **Отправка подборок**
   - Форматирование: заголовок, описание, цена, кнопка «Открыть»
   - Если несколько туров — показываем первый, остальные в кнопке «Еще»
   - Трекинг: кто открыл, кто кликнул

5. **Deep links в Mini App**
   - Формат: `https://t.me/MyTravelBot/app?startapp=collection_{token}`
   - При открытии Mini App — сразу показывает нужную подборку
   - Автоматическая авторизация через Telegram WebApp данные

6. **Rate limiting**
   - Не более 10 сообщений в минуту на пользователя
   - Блокировка на 5 минут при превышении
   - Логирование нарушителей

### BE-09: Уведомления и события

**User Stories:**

1. **Единая очередь уведомлений**
   - BullMQ очередь с приоритетами (high/medium/low)
   - High: горящие туры, напоминания о дедлайнах
   - Medium: падение цены, новые подписки
   - Low: дайджесты, статистические отчеты

2. **Каналы доставки**
   - Telegram (через бота)
   - Email (через Resend/SendGrid)
   - Push (Web Push API — для браузера, опционально)

3. **Шаблоны уведомлений**
   - Переменные: {{userName}}, {{tourName}}, {{price}}, {{collectionLink}}
   - Поддержка русского и английского языков
   - Редактирование шаблонов через админ-панель

4. **Throttling**
   - Не более 1 уведомления в 15 минут по одному туру
   - Не более 5 уведомлений в день на пользователя
   - Настройка per-user: можно изменить в профиле

5. **Статусы и логи**
   - pending → sent → delivered → read (для email)
   - pending → sent → read (для Telegram)
   - failed — с сохранением ошибки для отладки

6. **Retry logic**
   - При ошибке — повтор через 5 минут
   - Вторая ошибка — через 15 минут
   - Третья — через 1 час
   - После 3 ошибок — статус failed, уведомление в админ-панель

7. **Аналитика доставляемости**
   - Доставлено / открыто / кликнуто
   - Графики по дням
   - Анализ по типам уведомлений
