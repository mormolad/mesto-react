## 1.1 НАЗНАЧЕНИЕ И ОБЛАСТЬ ПРИМЕНЕНИЯ

### 1.1.1 Назначение системы

Система «VoiceLog Industrial» предназначена для автоматизации сбора, обработки и хранения оперативных отчётов инженеров промышленных предприятий посредством голосовых заметок.

**Основные цели внедрения:**
- Сокращение времени на составление отчёта с 2-3 минут (текстовый ввод) до 10-30 секунд (голосовая заметка)
- Централизованное хранение архива отчётов с возможностью поиска
- Автоматическое извлечение структурированных данных из голосовых сообщений
- Интеграция с системами напоминаний для контроля выполнения работ
- Обеспечение доказательной базы (аудиооригиналы) для разбора инцидентов

### 1.1.2 Область применения

Система применяется на промышленных объектах со следующими характеристиками:
- Наличие зон с нестабильным или отсутствующим интернет-соединением (цеха, подвалы, эстакады)
- Требования к хранению первичных данных (аудиозаписей)
- Необходимость быстрого поиска по архиву отчётов
- Работа с промышленной терминологией и аббревиатурами

**Целевая аудитория:**
- Инженеры по безопасности
- Оперативный персонал
- Технические специалисты
- Руководители подразделений
- Супервизоры

### 1.1.3 Границы системы

### 1.2.3 Сценарии взаимодействия

**Сценарий 1: Создание отчёта (онлайн)**
```
1. Пользователь нажимает «Записать»
2. Приложение записывает аудио (до 5 минут)
3. Сохранение локально в WatermelonDB
4. Отправка на сервер (POST /api/reports/upload)
5. Сервер возвращает reportId, статус «pending»
6. Worker обрабатывает: STT → LLM → Валидация
7. Обновление статуса на «completed»
8. Приложение получает уведомление (polling)
9. Отображение результата пользователю
```

**Сценарий 2: Создание отчёта (оффлайн)**
```
1. Пользователь нажимает «Записать»
2. Приложение записывает аудио
3. Сохранение локально (статус «pending»)
4. Проверка сети: нет соединения
5. Добавление в очередь синхронизации
6. При появлении сети: автоматическая отправка
7. Синхронизация статуса с сервером
```

**Сценарий 3: Поиск отчётов**
```
1. Пользователь открывает экран поиска
2. Вводит фильтры (дата, место, тип)
3. GET /api/reports?from=&to=&location=
4. PostgreSQL выполняет поиск с GIN-индексом
5. Возврат результатов (< 1 сек)
6. Отображение списка с возможностью фильтрации
```

### 1.4.2 Поведение при отсутствии прав

**Уровень UI:**
```
- Скрытие элементов управления (кнопки, меню)
- Блокировка действий с подсказкой «Нет прав»
- Серые (disabled) элементы для видимых, но недоступных функций
```

**Уровень API:**
```
- 401 Unauthorized — неаутентифицированный запрос
- 403 Forbidden — недостаточно прав
- 404 Not Found — для сокрытия существования ресурса (аудио других пользователей)
```

**Уровень БД:**
```
- Row Level Security (RLS) — фильтрация на уровне запросов
- Views с ограничением доступа — для отчётов супервизоров
```

### 1.8.1 Технические ограничения

| Ограничение | Влияние | Обход |
|-------------|---------|-------|
| **12GB VRAM (RTX 3060)** | Нельзя запустить 72B модель | Используем Qwen 14B Q4_K_M |

| **Локальное развёртывание** | Нет внешнего доступа | VPN для удалённой работы |
| **Один GPU** | Последовательная обработка | Очередь BullMQ |

### 1.8.2 Функциональные допущения

| Допущение | Риск | Mitigation |
|-----------|------|------------|
| **Точность STT 94-96%** | Может быть ниже на шумных записях | Предобработка аудио, ручная проверка |
| **Точность LLM 90-93%** | Может быть ниже на сленге | Few-shot примеры, дообучение |
| **Оффлайн до 24 часов** | Пользователи могут работать дольше | Увеличить лимит записей при необходимости |
| **JWT 30 дней без refresh** | Риск при утечке токена | Invalidate через БД, мониторинг |
| **Android 12+** | Старые устройства не поддерживаются | Требование к корпоративным устройствам |

### 1.8.3 Организационные ограничения

| Ограничение | Влияние | Решение |
|-------------|---------|---------|
| **Срок MVP 7 дней** | Ограниченный функционал | Фокус на критичные функции |
| **1 разработчик** | Узкое место | Cursor AI для ускорения |
| **Без выделенного админа** | Самостоятельная поддержка | Документация, скрипты деплоя |
| **Без тестировщика** | Риск багов в продакшене | Автотесты, ручное тестирование |

// Request
interface LoginRequest {
  username: string;      // 3-50 символов
  password: string;       // минимум 8 символов
  deviceId?: string;      // для идентификации устройства
}

// Response
interface LoginResponse {
  accessToken: string;    // JWT
  expiresIn: number;      // секунд (900 - 15 мин)
  user: {
    id: string;
    username: string;
    role: 'engineer' | 'supervisor' | 'admin';
    fullName: string;
    department: string | null;
    language: 'ru' | 'en';
  };
}

// Ошибки
interface ErrorResponse {
  error: string;          // код ошибки
  message: string;        // сообщение для пользователя
  details?: any;
}

**Локальное хранилище:**

```typescript
// WatermelonDB модель
interface LocalReport {
  id: string;
  userId: string;
  audioPath: string;        // локальный путь к файлу
  audioDuration: number;
  audioSize: number;
  status: LocalStatus;       // pending | synced | failed
  syncRetries: number;
  createdAt: Date;
  syncedAt?: Date;
  errorMessage?: string;
}

type LocalStatus = 
  | 'pending'    // ожидает отправки
  | 'syncing'    // в процессе отправки
  | 'synced'     // отправлено успешно
  | 'failed';    // ошибка после 5 попыток
```

**Конфигурация синхронизации:**

```typescript
interface SyncConfig {
  maxOfflineRecords: 10;        // максимум записей в очереди
  maxRetryAttempts: 5;          // максимум попыток
  retryBackoff: [1, 2, 4, 8, 16]; // минуты
  syncOnConnect: true;           // автосинхронизация при сети
  syncInterval: 30;              // проверка каждые 30 сек
  backgroundSync: true;          // фоновая синхронизация
  wifiOnly: false;               // синхронизация по любой сети
}
```

### 4.3.1 Локальное хранение

#### Сроки хранения

| Данные | Срок хранения | Действие по истечении |
|--------|---------------|------------------------|
| Синхронизированные отчёты | 30 дней | Автоматическое удаление |
| Несинхронизированные отчёты | Неограниченно | Ручное удаление |
| Аудиофайлы | 7 дней после синхронизации | Автоматическое удаление |

#### Индексы для локального поиска

| Поле | Тип индекса | Назначение |
|------|-------------|------------|
| created_at | B-tree | Сортировка по дате |
| status | B-tree | Фильтрация по статусу |
| transcribed_text | Full-text | Поиск по тексту |
| extracted_data->location | B-tree | Поиск по локации |

### 4.3.2 Очередь синхронизации

#### Приоритеты записей

| Приоритет | Типы записей | Поведение |
|-----------|--------------|-----------|
| **Высокий** | Новые отчёты, срочные | Отправляются первыми |
| **Средний** | Редактирования | После высокого приоритета |
| **Низкий** | Удаления, статистика | В последнюю очередь |

#### Политика повторных попыток

```
Попытка 1: через 1 минуту
Попытка 2: через 2 минуты
Попытка 3: через 4 минуты
Попытка 4: через 8 минут
Попытка 5: через 16 минут
После 5 попыток: статус "failed", уведомление пользователю
```

#### Ограничения очереди

| Параметр | Значение | Действие при превышении |
|----------|----------|-------------------------|
| Максимальный размер очереди | 100 записей | Блокировка новых записей |
| Максимальный размер файлов в очереди | 500 MB | Предупреждение, автоочистка старых |
| Максимальное время в очереди | 7 дней | Автоматическое удаление |

### 4.3.3 Сценарии синхронизации

#### Сценарий 4.3.3.1: Автоматическая при появлении сети
1. Мониторинг состояния сети (NetInfo)
2. При переходе offline → online проверка очереди
3. Если есть записи - запуск синхронизации
4. Отображение прогресса в статус-баре

#### Сценарий 4.3.3.2: Ручная (pull-to-refresh)
1. Пользователь тянет список вниз
2. Появляется индикатор обновления
3. Запуск синхронизации всех pending записей
4. Обновление списка с сервера

#### Сценарий 4.3.3.3: Фоновая (WorkManager)
1. Каждые 30 минут проверка сети и очереди
2. При наличии сети - синхронизация
3. Работает даже при закрытом приложении
