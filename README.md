## 1.1 НАЗНАЧЕНИЕ И ОБЛАСТЬ ПРИМЕНЕНИЯ

### 1.1.1 Назначение системы
Система «VoiceLog Industrial» предназначена для автоматизации сбора, обработки и хранения оперативных отчётов инженеров промышленных предприятий посредством голосовых заметок.

**Основные цели внедрения:**
*   Сокращение времени на составление отчёта с 2-3 минут (текстовый ввод) до 10-30 секунд (голосовая заметка)
*   Централизованное хранение архива отчётов с возможностью поиска
*   Автоматическое извлечение структурированных данных из голосовых сообщений
*   Интеграция с системами напоминаний для контроля выполнения работ
*   Обеспечение доказательной базы (аудиооригиналы) для разбора инцидентов

### 1.1.2 Область применения
Система применяется на промышленных объектах со следующими характеристиками:
*   Наличие зон с нестабильным или отсутствующим интернет-соединением (цеха, подвалы, эстакады)
*   Требования к хранению первичных данных (аудиозаписей)
*   Необходимость быстрого поиска по архиву отчётов
*   Работа с промышленной терминологией и аббревиатурами

**Целевая аудитория:**
*   Инженеры по безопасности
*   Оперативный персонал
*   Технические специалисты
*   Руководители подразделений
*   Супервизоры

### 1.2.2 Поток данных (Data Flow)

**Этапы обработки данных**

| Этап | Действие | Технология | Формат/Протокол | Результат |
| :--- | :--- | :--- | :--- | :--- |
| 1. Запись аудио | Запись голосовой заметки | MediaRecorder (React Native) | OGG/OPUS, 16kHz, моно | Аудиофайл локально |
| 2. Локальное сохранение | Сохранение в хранилище устройства | WatermelonDB + RNFS | SQLite + файловая система | Запись в БД со статусом pending |
| 3. Отправка на сервер | Передача аудиофайла | HTTPS POST | JWT Cookie, multipart/form-data | reportId, статус pending |
| 4. Очередь обработки | Постановка в очередь | BullMQ (Redis) | JSON задача | Задача в очереди report-processing |
| 5. STT обработка | Транскрибация аудио → текст | faster-whisper (medium) | Audio → Text | Распознанный текст |
| 6. LLM обработка | Парсинг текста → структурированные данные | Ollama Qwen 14B Q4_K_M | Text → JSON | Извлечённые поля (локация, тип, описание и т.д.) |
| 7. Валидация | Проверка JSON схемы | AJV Validator | JSON Schema | Валидный/невалидный JSON |
| 8. Сохранение результата | Запись в БД и хранилище | PostgreSQL + MinIO | SQL + S3 API | Отчёт в БД, аудио в MinIO |
| 9. Синхронизация | Обновление статуса на клиенте | Polling / WebSocket | HTTPS | Статус completed на устройстве |

**Статусы отчёта в потоке обработки**

| Статус | Где отображается | Значение | Следующий статус |
| :--- | :--- | :--- | :--- |
| pending | Mobile + Backend | Ожидает отправки/обработки | processing |
| processing | Backend | В обработке (STT/LLM) | completed / failed |
| completed | Mobile + Backend | Обработка завершена успешно | — |
| failed | Mobile + Backend | Ошибка обработки | pending (retry) |
| review | Backend | Требуется ручная проверка | completed / failed |

### 1.2.3 Сценарии взаимодействия

**Сценарий 1: Создание отчёта (онлайн)**
1.  Пользователь нажимает «Записать»
2.  Приложение записывает аудио (до 5 минут)
3.  Сохранение локально в WatermelonDB
4.  Отправка на сервер (POST /api/reports/upload)
5.  Сервер возвращает reportId, статус «pending»
6.  Worker обрабатывает: STT → LLM → Валидация
7.  Обновление статуса на «completed»
8.  Приложение получает уведомление (polling)
9.  Отображение результата пользователю

**Сценарий 2: Создание отчёта (оффлайн)**
1.  Пользователь нажимает «Записать»
2.  Приложение записывает аудио
3.  Сохранение локально (статус «pending»)
4.  Проверка сети: нет соединения
5.  Добавление в очередь синхронизации
6.  При появлении сети: автоматическая отправка
7.  Синхронизация статуса с сервером

**Сценарий 3: Поиск отчётов**
1.  Пользователь открывает экран поиска
2.  Вводит фильтры (дата, место, тип)
3.  GET /api/reports?from=&to=&location=
4.  PostgreSQL выполняет поиск с GIN-индексом
5.  Возврат результатов (< 1 сек)
6.  Отображение списка с возможностью фильтрации

### 1.4.2 Поведение при отсутствии прав

**Уровень UI:**
*   Скрытие элементов управления (кнопки, меню)
*   Блокировка действий с подсказкой «Нет прав»
*   Серые (disabled) элементы для видимых, но недоступных функций

**Уровень API:**
*   401 Unauthorized — неаутентифицированный запрос
*   403 Forbidden — недостаточно прав
*   404 Not Found — для сокрытия существования ресурса (аудио других пользователей)

**Уровень БД:**
*   Row Level Security (RLS) — фильтрация на уровне запросов
*   Views с ограничением доступа — для отчётов супервизоров

| F-01.05 | Отображение ошибок аутентификации | 🔴 Критично |

| F-01.08 | Refresh token (обновление токена) | 🟢 Этап 2 |

**User Story:**
> Как инженер,  
> Я хочу войти в приложение под своим аккаунтом,

**Интерфейсы API:**
```typescript
// Request
interface LoginRequest {
  username: string;      // 3-50 символов
  password: string;      // минимум 8 символов
  deviceId?: string;     // для идентификации устройства
}

// Response
interface LoginResponse {
  accessToken: string;   // JWT
  expiresIn: number;     // секунд (900 - 15 мин)
  user: {
    id: string;
    username: string;
    role: 'engineer' | 'supervisor' | 'admin';
    fullName: string;
    department: string | null;
    language: 'ru' | 'en';
  };
}

// Ошибки
interface ErrorResponse {
  error: string;         // код ошибки
  message: string;       // сообщение для пользователя
  details?: any;
}
```

**Коды ошибок:**

| Код | Сообщение пользователю | Действие |
|-----|------------------------|----------|
| 401 | «Неверный логин или пароль» | Очистить поле пароля |
| 403 | «Аккаунт заблокирован. Обратитесь к администратору» | Блокировка входа |
| 429 | «Слишком много попыток. Попробуйте через 15 минут» | Таймер обратного отсчёта |
| 500 | «Ошибка сервера. Повторите позже» | Кнопка повтора |
| -1 | «Нет соединения с интернетом» | Проверка сети |

| **Loading** | Спиннер на кнопке, поля disabled | Отправка запроса |
| **Validation Error** | Подсветка полей, сообщение об ошибке | Фокус на первом ошибочном поле |
| **Server Error** | Сообщение об ошибке над кнопкой | Кнопка активна для повтора |
| **Locked** | Сообщение о блокировке, таймер | Кнопка неактивна до разблокировки |

**Локальное хранилище:**
```typescript
// WatermelonDB модель
interface LocalReport {
  id: string;
  userId: string;
  audioPath: string;        // локальный путь к файлу
  audioDuration: number;
  audioSize: number;
  status: LocalStatus;      // pending | synced | failed
  syncRetries: number;
  createdAt: Date;
  syncedAt?: Date;
  errorMessage?: string;
}

type LocalStatus = 
  | 'pending'    // ожидает отправки
  | 'syncing'    // в процессе отправки
  | 'synced'     // отправлено успешно
  | 'failed';    // ошибка после 5 попыток
```

**Конфигурация синхронизации:**
```typescript
interface SyncConfig {

  syncOnConnect: true;             // автосинхронизация при сети

  wifiOnly: false;                 // синхронизация по любой сети
}
```

### 3.3.7 Технические параметры записи

```typescript
const audioConfig = {
  // Формат
  sampleRate: 16000,           // Hz (оптимально для Whisper)
  channels: 1,                 // моно
  bitsPerSample: 16,           // бит
  outputFormat: 'audio/ogg',   // кодек OPUS
  quality: 0.8,                // качество сжатия
  
  // Ограничения
  maxDuration: 300,            // 5 минут (жесткий лимит)
  minDuration: 2,              // 2 секунды (защита от случайных)
  
  // Обработка сигнала
  autoGain: true,              // автоматическая регулировка усиления
  noiseSuppression: true,      // подавление шума
  
  // Визуализация
  waveformBars: 13,            // количество полос
  animationDuration: 1.2,      // секунды на анимацию
  updateInterval: 100          // мс между обновлениями waveform
};
```

### 3.3.8 Обработка граничных случаев

| Ситуация | Поведение системы |
|----------|-------------------|
| **Достигнут лимит 5:00** | Автоматическая остановка → сохранение → переход в Processing |
| **Запись < 2 секунд** | Предупреждение: «Запись слишком короткая» → возврат в Idle |
| **Входящий звонок** | Пауза записи → возобновление после завершения звонка |
| **Нет разрешения на микрофон** | Запрос системного разрешения → при отказе показ инструкции с кнопкой «Открыть настройки» |
| **Недостаточно места** | Ошибка: «Недостаточно памяти» → предложение очистить кэш |
| **Потеря соединения во время сохранения** | Локальное сохранение → добавление в очередь синхронизации |
| **Свайп назад во время записи** | Диалог: «Запись будет потеряна. Отменить?» → [Отменить] / [Продолжить] |

### 3.3.9 Доступность (Accessibility)

| Требование | Реализация |
|------------|------------|
| **ARIA-метки** | `aria-label` на кнопке микрофона меняется: «Начать запись» ↔ «Остановить запись» |
| **Screen reader** | `aria-live="polite"` регион для озвучивания статуса: «Запись начата» / «Запись остановлена» |
| **Фокус клавиатуры** | `:focus-visible` с контуром `#2196F3`, `tabindex="0"` на интерактивных элементах |
| **Контрастность** | Текст на кнопке белый на синем/красном фоне — контраст ≥ 4.5:1 |
| **Минимальный размер** | Кнопка микрофона 120×120 px > 44×44 px минимума |
| **Анимация** | Возможность отключения анимации через `prefers-reduced-motion` (Этап 2) |

### 3.3.10 Анимации и переходы

| Элемент | Анимация | Длительность | Easing |
|---------|----------|--------------|--------|
| Кнопка микрофона (hover) | `scale(1.02)` | 200 мс | ease-out |
| Кнопка микрофона (active) | `scale(0.98)` | 100 мс | ease-in |
| Пульсация 🔴 индикатора | `opacity + scale` | 1.4 мс бесконечно | ease-in-out |
| Waveform bars | `scaleY + opacity` | 0.8–1.5 мс (разные) | alternate ease-in-out |
| Смена цвета таймера | `color` | 300 мс | linear |
| Переход между экранами | `scale down + fade` | 250 мс | ease-out |

### 4.3.2 Очередь синхронизации

#### Приоритеты записей

| Приоритет | Типы записей | Поведение |
|-----------|--------------|-----------|
| 🔴 **Высокий** | Новые отчёты, срочные | Отправляются первыми |
| 🟡 **Средний** | Редактирования | После высокого приоритета |
| 🟢 **Низкий** | Удаления, статистика | В последнюю очередь |

#### Политика повторных попыток

```
Попытка 1: через 1 минуту
Попытка 2: через 2 минуты
Попытка 3: через 4 минуты
Попытка 4: через 8 минут
Попытка 5: через 16 минут
→ После 5 попыток: статус "failed", уведомление пользователю
```

#### Ограничения очереди

| Параметр | Значение | Действие при превышении |
|----------|----------|-------------------------|
| Максимальный размер очереди | 100 записей | Блокировка новых записей |
| Максимальный размер файлов в очереди | 500 MB | Предупреждение, автоочистка старых |
| Максимальное время в очереди | 7 дней | Автоматическое удаление |

### 4.3.3 Сценарии синхронизации

#### 🔄 Сценарий: Автоматическая при появлении сети
```
1. Мониторинг состояния сети (NetInfo)
2. При переходе offline → online проверка очереди
3. Если есть записи — запуск синхронизации
4. Отображение прогресса в статус-баре
```

#### 👇 Сценарий: Ручная (pull-to-refresh)
```
1. Пользователь тянет список вниз
2. Появляется индикатор обновления
3. Запуск синхронизации всех pending записей
4. Обновление списка с сервера
```

#### ⚙️ Сценарий: Фоновая (WorkManager)
```
1. Каждые 30 минут проверка сети и очереди
2. При наличии сети — синхронизация
3. Работает даже при закрытом приложении
```
