# 1. ВВЕДЕНИЕ И БИЗНЕС-ЦЕННОСТЬ

## Проблема

Современные турагенты сталкиваются с рядом вызовов:
- **Разрозненные инструменты** — Excel, CRM, мессенджеры — все отдельно
- **Ручной мониторинг цен** — упущенная прибыль и недовольные клиенты
- **Сложность создания предложений** — каждый тур нужно оформлять вручную
- **Потеря клиентов** — нет системы уведомлений и напоминаний
- **Отсутствие аналитики** — непонятно, что работает, а что нет

## Решение

Мы создаем **единую экосистему** для турагента с интеграцией в **MAX** — профессиональный мессенджер для бизнеса:

```
┌─────────────────────────────────────────────────────────────────┐
│                    ЕДИНОЕ ПРИЛОЖЕНИЕ                             │
├─────────────────────────────────────────────────────────────────┤
│  Для агента:          Для туриста:                              │
│  • Поиск туров        • Просмотр подборок                       │
│  • Конструктор        • Подписка на изменения                   │
│    подборок           • Графики цен                             │
│  • CRM с клиентами    • Уведомления в MAX                       │
│  • Финансовый учет    • Быстрая связь с агентом через MAX       │
│  • База знаний        • История просмотров                      │
│  • SMM-инструменты                                              │
└─────────────────────────────────────────────────────────────────┘
```

## Бизнес-ценность

| Показатель | Эффект | Как достигается |
|------------|--------|-----------------|
| **Экономия времени агента** | до 15 часов в неделю | Автоматизация подборок, шаблоны, поиск |
| **Рост конверсии** | +30-50% | Персонализированные подборки, уведомления в MAX |
| **Повышение LTV клиента** | +40% | Система подписок, напоминания, история |
| **Снижение оттока** | -25% | Умные уведомления о снижении цен через MAX |
| **Увеличение маржи** | +15% | Калькулятор, аналитика, оптимизация |

# 3. ТЕХНОЛОГИЧЕСКИЙ СТЕК (ОБОСНОВАНИЕ)

## Почему эти технологии?

### Фронтенд: Next.js 16 + React 19

| Критерий | Выбор | Обоснование |
|----------|-------|-------------|
| **Производительность** | Server Components | SEO-страницы рендерятся на сервере, быстрая загрузка |
| **Разработка** | App Router | Встроенный роутинг, layout-ы, параллельные роуты |
| **SEO** | Metadata API | Автоматическая генерация мета-тегов, sitemap |
| **Скорость разработки** | Turbopack | Горячая перезагрузка, быстрая сборка |
| **Масштабируемость** | React Server Components | Минимум JS на клиенте |

**Альтернативы, которые отклонили:**
- **Vite + React Router** — нет SSR, хуже для SEO, больше кода для роутинга
- **Gatsby** — сложнее с динамическими данными
- **Create React App** — устарел, нет SSR

---

### Бэкенд: NestJS 11

| Критерий | Выбор | Обоснование |
|----------|-------|-------------|
| **Структура** | Модульная архитектура | Четкое разделение, легко поддерживать |
| **TypeScript** | Первый класс | Типизация на всем стеке |
| **DI (Dependency Injection)** | Встроенный | Легкое тестирование, модульность |
| **Очереди** | BullMQ интеграция | Фоновые задачи из коробки |
| **WebSocket** | Встроенный Gateway | Real-time уведомления |
| **Документация** | Swagger/OpenAPI | Автоматическая генерация |

**Альтернативы, которые отклонили:**
- **Express** — слишком низкоуровнево, больше кода
- **Fastify** — меньше экосистемы, сложнее найти решения
- **Django** — Python медленнее, сложнее типизация

---

### База данных: PostgreSQL 17

| Критерий | Выбор | Обоснование |
|----------|-------|-------------|
| **Надежность** | ACID транзакции | Критично для финансовых операций |
| **Поиск** | pg_trgm, полнотекстовый | ElasticSearch не нужен на старте |
| **JSON** | JSONB тип | Гибкие данные (удобства отелей, настройки) |
| **Репликация** | Встроенная | Масштабирование в будущем |
| **Бекапы** | pg_dump + WAL | Точки восстановления |

---

### Кэш и очереди: Redis 7.4

| Критерий | Выбор | Обоснование |
|----------|-------|-------------|
| **Скорость** | In-memory | < 1ms latency |
| **Кэширование** | TTL, eviction | Гибкое управление |
| **Очереди** | BullMQ (на Redis) | Надежные очереди с retry |
| **Сессии** | Redis Store | Автоматическое истечение |
| **Rate limiting** | Redis счетчики | Защита от спама |

---

### Интеграция с MAX

| Критерий | Выбор | Обоснование |
|----------|-------|-------------|
| **API MAX** | REST API | Стандартный протокол |
| **Deep Links** | `max://` scheme | Глубокие ссылки в мобильном приложении |
| **Уведомления** | MAX Business API | Официальный канал уведомлений |
| **Авторизация** | OAuth 2.0 | Безопасная интеграция |

**Преимущества MAX перед WhatsApp:**
- Профессиональный инструмент для бизнеса
- API для автоматизации
- Нет ограничений на коммерческие сообщения
- Возможность массовой рассылки

---

## Обоснование выбора стека для одного разработчика

| Фактор | Как помогает |
|--------|--------------|
| **Единый язык (TypeScript)** | Не нужно переключаться между языками |
| **Генерация кода** | NestJS CLI, Prisma, shadcn/ui — меньше рутины |
| **Готовые компоненты** | shadcn/ui — 50% фронтенда готово |
| **Автоматическая документация** | Swagger, Prisma Studio |
| **Docker** | Локальный запуск за 5 минут |
| **Vercel (frontend) + VPS (backend)** | Простой деплой |

# 7. РИСКИ И ИХ МИНИМИЗАЦИЯ

## Технические риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| **API туроператоров нестабильны** | Высокая | Среднее | Ручной ввод на старте, кэширование, circuit breaker |
| **MAX API изменения** | Средняя | Среднее | Адаптерный слой, документация MAX |
| **PDF генерация нагружает сервер** | Средняя | Среднее | Отдельный воркер, очередь, клиентская генерация для простых PDF |
| **Рост базы данных** | Средняя | Низкое | Индексы, партиционирование, архив старых данных |
| **Безопасность (XSS, CSRF)** | Низкая | Высокое | httpOnly cookies, CSP, helmet.js, регулярный аудит |

---

## Бизнес-риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
